# 🎨 フロントエンド・リファレンス (Frontend Reference)

本ドキュメントは、AI Radio Room フロントエンドシステムの設計思想、データ構造、および「スタジオ・モニター型」UI の処理フローを詳細に解説する。

---

## 🎙️ 1. ユーザー体験 (UX) フロー

ユーザーがブラウザでアプリを開き、AI ラジオの放送を開始・視聴するまでのシームレスな体験を定義。

### 1.1 初期化フェーズ
> **[Setup]** ブラウザ起動時の DOM 構築とリソース準備。

1.  **🚀 エントリポイント**: `src/main.ts` が読み込まれ、`DOMContentLoaded` を起点に `MonitorUI` と `VoicePlayer` が初期化される。
2.  **💎 デザイン適用**: body に `.ready` クラスが付与され、FOUC（スタイル崩れ）を防ぎながらフェードインする。
3.  **📻 スタジオ準備**: アバターの配置、ビジュアライザーの初期化、BGM プレイヤーの生成が行われる。

### 1.2 放送・ストリーミングフェーズ
> **[On Air]** バックエンドから SSE (Server-Sent Events) を受信し、同期再生を行う。

-   **📡 接続**: `fetch` API のストリームリーダーを用い、`/api/broadcasts` から逐次データを受信。
-   **🎧 同期再生の三原則**:
    1.  **受信**: SSE から `ScriptItem` を取得し、再生キューに追加。
    2.  **先行取得 (Pre-fetch)**: 再生される前に、裏側で `/api/tts` から音声をダウンロード。
    3.  **発火**: 音声が鳴る瞬間に `MonitorUI` を更新し、アバターを動かしてテロップを表示。

## 💎 2. スタジオ・コンポーネント

### 📡 ライブモニター (`MonitorUI.ts`)
| 機能 | 説明 |
| :--- | :--- |
| **アバター制御** | 喋っているキャラクターの彩度を上げ、浮き上がらせる演出。 |
| **ライブテロップ** | 画面表示用テキスト（`text`）をタイプライター風に描画。 |
| **ビジュアライザー** | 背景で稼働する音声波形の疑似アニメーション。 |

### 🔊 ボイスプレイヤー (`VoicePlayer.ts`)
-   **シーケンシャル・キュー**: ネットワーク負荷を抑えるため、音声の取得を 1 つずつ順番に実行。
-   **Blob URL 管理**: 取得した音声データをメモリ上に保持し、再生終了後に適切に解放。

## 🛠️ 3. データ定義 (TypeScript)

バックエンドの Go 構造体と完全に整合する型定義。

### 📝 `ScriptItem` (セリフデータ)
```typescript
export interface ScriptItem {
  speaker: string;    // mc, guest-a, guest-b
  speaker_id: number; // VOICEVOX スタイル ID
  text: string;       // 画面用（漢字・英語あり）
  audio_text: string; // 音声用（カナ・読み仮名主体）
  emotion: string;    // normal, excited, calm
}
```

## 📁 4. ディレクトリ構成

-   `src/main.ts`: 全体のオーケストレーション。
-   `src/ui/monitor.ts`: 放送中の視覚演出とテロップ管理。
-   `src/voice/player.ts`: 音声のキューイング、ロード、再生。
-   `src/types/`: 型定義ファイル。
-   `style.css`: ニューモーフィズム & グラスモーフィズムの定義。
